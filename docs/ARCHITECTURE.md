# معماری Armando Group Manager

## جریان یک آپدیت

```
Telegram ──▶ Dispatcher
              │
              ├─ DbSessionMiddleware      (یک نشست دیتابیس برای هر آپدیت + commit/rollback)
              ├─ ThrottlingMiddleware     (محافظت از خود ربات روی Callbackها)
              ├─ ChatTrackingMiddleware   (به‌روزرسانی سبک metadata گروه، حداکثر یک‌بار در دقیقه)
              │
              ├─ handlers/commands.py     دستورات اسلش + دیسپچر متن فارسی
              │     └─ registry.match()   تطبیق با طولانی‌ترین الگو (بدون اسلش)
              ├─ handlers/panel.py        پنل شیشه‌ای سلسله‌مراتبی (Callbackها)
              ├─ handlers/messages.py     خطای پردازش پیام‌های غیر دستوری
              ├─ handlers/members.py      ورود/خروج/کپچا/سرویس‌مسج‌ها
              └─ handlers/errors.py       مدیر سراسری خطا (یک آپدیت خراب، ربات را نمی‌خواباند)
```

## خط پردازش پیام‌های غیر دستوری (`handlers/messages.py`)

```
AFK ──▶ حالت شب ──▶ قفل‌ها (لینک/رسانه/...) ──▶ ضد فحاشی ──▶ ضد پورن
  ──▶ لیست سیاه ──▶ ضد فلود ──▶ ضد اسپم ──▶ هوش مصنوعی (اختیاری)
  ──▶ تریگرها (استیکر/گیف جادویی، #تگ، دستور شخصی، فیلترها، نام یادداشت)
  ──▶ امتیاز (±) ──▶ بازی حدس
```

هر مرحله می‌تواند زنجیره را متوقف کند (`Stop`)؛ هیچ مرحله‌ای در صورت خطا کل ربات را
از کار نمی‌اندازد (همهٔ فراخوانی‌های تلگرام با `safe_call` محافظت می‌شوند).

## مدل دسترسی (دو لایه)

1. **دسترسی واقعی تلگرام** — از `getChatMember` خوانده می‌شود (creator/administrator و فلگ‌های دسترسی).
2. **نقش داخلی** — ۱۰ سطح در `services/roles.py`:
   `member < trusted < vip < cleaner < helper < muter < moderator < admin < cofounder < founder`

اجازه تنها زمانی صادر می‌شود که **هر دو لایه موافق باشند**؛ بنابراین ربات هرگز ابزار
افزایش دسترسی (Privilege Escalation) نیست. مالک گروه، ادمین‌ها، ربات و ادمین‌های ناشناس
در برابر اقدام محافظت می‌شوند (`services/permissions.py::check_target`).

## ثبت دستورات

دستورات با دکوراتور `@command(...)` در `handlers/registry.py` ثبت می‌شوند:

```python
@command("بن", "بن کردن", role="moderator", permission="ban",
         category="moderation", usage="بن [مدت] [دلیل]")
async def cmd_ban(ctx: CommandContext) -> None: ...
```

- ایندکس بر پایهٔ **طولانی‌ترین پیشوند** است، بنابراین `تنظیم قوانین` بر `تنظیم` غلبه می‌کند.
- تطبیق فقط روی توکن‌های دقیق انجام می‌شود تا متن عادی گفتگو (`بنظرم …`) دستور تلقی نشود.
- هر دستور یک «نوع آرگومان» دارد که در `ARG_RULES` تعریف شده است:
  * `none` — پیام باید دقیقاً همان عبارت باشد (`تاریخ`، `ارز دیجیتال`، `پنل`)
  * `keys` — آرگومان‌ها باید کلیدواژهٔ معتبر باشند (`قفل لینک`، `قیمت دلار`)
  * `numeric` — آرگومان باید عدد/زمان باشد (`پاکسازی ۱۰۰`، `تعداد اخطار ۴`)
  * `free` — متن کوتاه، یا نامحدود بعد از `=` (`ذخیره قوانین = …`)
  به این ترتیب جمله‌هایی مثل «قیمت دلار چقدر گرون شده» هیچ‌وقت دستور محسوب نمی‌شوند.
- برای هر دستور سطح نقش و «گذرگاه دسترسی» تعریف شده است (`ban/delete/restrict/promote/pin/...`).

## دیتابیس

- SQLAlchemy 2.x ORM، **SQLite پیش‌فرض** و **سازگار با Postgres**.
- ۲۵ مدل با ایندکس روی مسیرهای پُرجستجو (`(chat_id, user_id)`, `(scope, active)`, …).
- `db/migrate.py` مهاجرت‌های افزایشی سبک را اعمال می‌کند (ایمن برای اجرای مجدد).
- کش‌های TTL در حافظه برای تنظیمات، قفل‌ها، فیلترها، نقش‌ها و وضعیت اعضا (با ابطال هدفمند).

## زمان‌بند

`services/scheduler.py` در همان_process اجرا می‌شود: انقضای محدودیت‌ها/بن‌ها،
یادداشت‌های زمان‌بندی‌شده، پاک‌سازی کش‌ها و ثبت اسنپ‌شات روزانهٔ آمار.

## بازار و زمان

- بازار: `tgju → coingecko → erapi → nobitex → wallex` (ترتیب با `MARKET_PROVIDER_ORDER`
  قابل تنظیم است). همهٔ منابع رایگان و بدون کلید هستند و خرابی هر منجر به خطا نمی‌شود.
- زمان: محاسبهٔ آفلاین با `jdatetime` و `zoneinfo`؛ همگام‌سازی اختیاری با API عمومی زمان.
